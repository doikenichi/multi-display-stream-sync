# Implementation Roadmap

## Purpose

This document defines an incremental implementation path for the **Multi-Display Stream Synchronization Test Lab**.

The roadmap starts with the simplest possible local operating system proof using only FFmpeg, then gradually evolves toward the full project architecture:

```text
FFmpeg → MediaMTX → HLS → Browser Display Clients → Java Test Framework → Evidence Artifacts → CI/CD
```

The goal is to build confidence step by step, avoid unnecessary early complexity, and keep every milestone demonstrable.

---

## Phase 0 — Local FFmpeg Smoke Test

### Goal

Prove that a synthetic video can be generated locally.

### Use

```text
OS terminal
FFmpeg
local video output
```

### Build

1. Install FFmpeg.
2. Generate a simple test video with a frame counter and text overlay.
3. Save it as a local `.mp4`.
4. Open the video manually and confirm:
   - the video plays;
   - the frame counter or text is visible;
   - FPS and resolution are correct.

### Example Command

```bash
ffmpeg -f lavfi -i "testsrc=size=1280x720:rate=30" \
  -t 30 \
  -vf "drawtext=text='SOURCE\: CAMERA_SYNC_TEST FRAME\: %{n} TIME\: %{pts\:hms}':x=40:y=40:fontsize=36:fontcolor=white:box=1:boxcolor=black@0.6" \
  -c:v libx264 \
  -pix_fmt yuv420p \
  test-output.mp4
```

```powershell
ffmpeg -f lavfi -i "testsrc=size=1280x720:rate=30" `
  -t 30 `
  -vf "drawtext=fontfile='C\:/Windows/Fonts/arial.ttf':text='SOURCE\: CAMERA_SYNC_TEST FRAME\: %{n} TIME\: %{pts\:hms}':x=40:y=40:fontsize=36:fontcolor=white:box=1:boxcolor=black@0.6" `
  -c:v libx264 `
  -pix_fmt yuv420p `
  test-output.mp4
```

```cmd
ffmpeg -f lavfi -i "testsrc=size=1280x720:rate=30" ^
  -t 30 ^
  -vf "drawtext=fontfile='C\:/Windows/Fonts/arial.ttf':text='SOURCE\: CAMERA_SYNC_TEST FRAME\: %{n} TIME\: %{pts\:hms}':x=40:y=40:fontsize=36:fontcolor=white:box=1:boxcolor=black@0.6" ^
  -c:v libx264 ^
  -pix_fmt yuv420p ^
  test-output.mp4
```

the main changes are
```
Linux/macOS line continuation: \
PowerShell line continuation: `
CMD line continuation: ^
Windows font path: C\:/Windows/Fonts/arial.ttf
```

### Done When

```text
You can create and play a local synthetic test video.
```

## Phase 1 — FFmpeg Live Stream to MediaMTX

### Goal

Prove the basic streaming path.

### Use

```text
FFmpeg → MediaMTX → HLS endpoint
```

### Build

1. Run MediaMTX locally.
2. Publish FFmpeg test video to MediaMTX using RTSP.
3. Open the HLS stream URL in a browser or test HTML page.
4. Confirm that the stream is visible.

### Target Flow

```text
FFmpeg testsrc
  ↓
MediaMTX
  ↓
HLS URL
  ↓
Browser
```

### Done When

```text
A browser can play a live HLS stream generated by FFmpeg.
```

## Phase 2 — Simple Browser Display Client

### Goal

Create the first browser-based virtual display.

### Use

```text
HTML
hls.js
```

### Build

1. Create a `display-client/` app.
2. Add one HTML page that accepts query parameters:
   - `displayId`
   - `source`
   - `streamUrl`
3. Use `hls.js` to load the HLS URL.
4. Show display identity on the page.

### Example URL

```text
http://localhost:3000/display.html?displayId=DISPLAY_01&source=CAMERA_SYNC_TEST
```

### Done When

```text
DISPLAY_01 can render the HLS stream in the browser.
```

## Phase 5 — Basic Artifact Structure

### Goal

Start treating every run as evidence-producing.

### Build

1. Generate a simple `testRunId`.
2. Create this folder structure:

```text
artifacts/
  runs/
    {testRunId}/
      summary.json
      screenshots/
      logs/
  latest/
```

3. Copy or update the latest run into:

```text
artifacts/latest/
```

4. Write a minimal `summary.json`.

### Example Minimal `summary.json`

```json
{
  "testRunId": "LOCAL_RUN_001",
  "sourceId": "CAMERA_SYNC_TEST",
  "protocol": "HLS",
  "result": "PASS",
  "displayCount": 1,
  "startedAt": "2026-06-05T14:00:00Z",
  "endedAt": "2026-06-05T14:00:30Z"
}
```

### Done When

```text
Every test run leaves a reusable artifact folder.
```

Replace manual FFmpeg lifecycle with an API.

### Use

```text
Streaming Lab Orchestration API
```

### Build

1. Create `stream-orchestrator/`.

   - create test run;
   - start stream;
   - get stream status;

   - get artifact locations.
3. The Java framework should call the API instead of starting FFmpeg directly.
4. The API should manage the FFmpeg process lifecycle.

Streaming Lab Orchestration API
  ↓
FFmpeg
  ↓
MediaMTX
```

```

## Phase 10 — Pre-Generated Frame Sequence

### Goal

Move from FFmpeg `testsrc` to deterministic generated frames.

### Build

1. Add frame generator logic.
2. Generate PNG frames before streaming.
3. Each frame should contain:
   - source ID;
   - test run ID;
   - sequence ID;
   - frame number;
   - FPS;
   - expected presentation timestamp;
   - human-readable text.
4. Stream those frames through FFmpeg image sequence input.

### Target Flow

```text
Generate PNG frames
  ↓
FFmpeg image sequence input
  ↓
MediaMTX
  ↓
HLS
  ↓
Browser clients
```

### Done When

```text
Each run has its own generated frame sequence and stream content.
```

## Phase 11 — QR Code Marker Support

### Goal

Make validation deterministic instead of relying on visible text.

### Build

1. Add QR code generation to each frame.
2. Encode marker payload as JSON.
3. Add a Java marker decoder.
4. Decode screenshots or captured frames from each display.
5. Save decoded samples.

### Marker Payload

```json
{
  "source": "CAMERA_SYNC_TEST",
  "testRunId": "SYNC_RUN_001",
  "sequenceId": "SEQ_001",
  "frame": 184,
  "fps": 30,
  "presentationTimeMs": 6133.333,
  "expectedPresentationEpochMs": 1780689606133
}
```

### Done When

```text
The Java framework can decode the displayed frame marker and extract the frame number.
```

## Phase 12 — Source and Test Run Validation

### Goal

Verify that displays are showing the correct stream.

### Build Assertions For

1. Marker exists.
2. `source` matches the expected source.
3. `testRunId` matches the active run.
4. `sequenceId` matches the active sequence.

### Failure Examples

```text
Missing marker
Wrong source
Wrong testRunId
Stale stream from previous run
```

### Done When

```text
The test fails if a display is showing the wrong or stale stream.
```

## Phase 13 — Frame Progression Validation

### Goal

Verify that each display keeps moving forward.

### Build

1. Capture repeated samples from each display.
2. Decode the frame number from each sample.
3. Confirm frame numbers increase over time.
4. Save samples to:

```text
raw/marker-samples.jsonl
```

### Done When

```text
The test can detect a display that stops advancing.
```

---

## Phase 14 — Multi-Display Offset Validation

### Goal

Validate synchronization across displays.

### Build

1. Capture samples from all displays at each interval.
2. Decode the frame number for each display.
3. Calculate:

```text
maxFrameOffset = max(frame) - min(frame)
```

4. Save results to:

```text
offsets.csv
```

5. Fail if the offset exceeds tolerance.

### Example

```text
DISPLAY_01 frame = 1050
DISPLAY_02 frame = 1049
DISPLAY_03 frame = 1051

maxFrameOffset = 2
toleranceFrames = 3
result = PASS
```

### Done When

```text
The framework can pass or fail based on frame offset between displays.
```

---

## Phase 15 — Frozen Display Detection

### Goal

Detect a display that remains stuck.

### Build

1. Track the last progressing frame per display.
2. Track how long the frame has not advanced.
3. Fail when stale duration exceeds the configured timeout.
4. Save:
   - screenshot;
   - marker samples;
   - failure reason;
   - failure summary.

### Done When

```text
A frozen display produces a clear failure with evidence.
```

---

## Phase 16 — Latency Mode

### Goal

Measure observed browser render latency.

### Build

1. Pre-arm display clients before the stream starts.
2. Start packet capture if enabled.
3. Start the stream through the orchestration API.
4. Capture the first visible decoded frame.
5. Calculate:

```text
observedRenderLatencyMs = browserCaptureTimeMs - expectedPresentationEpochMs
```

6. Save latency data to:

```text
latency.csv
```

### Done When

```text
The framework can report first observed frame and observed browser render latency.
```
